## Where configuration belongs

| Location | Proposed values | Secret? |
|---|---|---|
| Convex development/production environment | `TYPESAFE_API_KEY`, `OPENAI_API_KEY`, `FIRECRAWL_API_KEY`, `AGENTMAIL_API_KEY` | Yes; backend only |
| Convex environment | Provider webhook signing secret, if required by chosen webhook integration | Yes; use documented name/verification mechanism |
| Convex environment | `FLOWSTATE_JEV_MODEL`, `FLOWSTATE_VISION_MODEL`, `FLOWSTATE_PLANNER_MODEL` | No; pin tested versions, do not select unverified defaults |
| Convex environment | `FLOWSTATE_ALLOWED_TEST_RECIPIENTS`, `FLOWSTATE_AGENTMAIL_INBOX_ID` | Not authentication secrets, but keep private and server-side |
| Convex environment | `FLOWSTATE_DAILY_BUDGET_USD`, `FLOWSTATE_MAX_RUN_STEPS`, `FLOWSTATE_HISTORY_RETENTION_DAYS` | Policy settings; require implementation and tests to enforce them |
| Ignored local CLI configuration | Convex deployment selection generated by setup; CI deployment credential only when needed | Deployment credential is secret; keep out of app bundles |
| Web local environment | `VITE_CONVEX_URL`, `VITE_CLERK_PUBLISHABLE_KEY` | Public; all Vite-exposed values must be safe to publish |
| Native ignored `.xcconfig` | Convex URL, auth public client ID/callback, bundle ID, team ID | Public configuration; no managed provider keys |
| macOS Keychain | User session/refresh tokens and device credentials | Yes; never copy to web or logs |
| CI secret store | Deployment/signing/notarization credentials when CI release is configured | Yes; scoped to required environments |

Use separate development and production resources. A configuration value alone does not implement a spending cap, retention job or permission check. Set provider-side limits where supported and enforce application-level limits as part of the implementation.
