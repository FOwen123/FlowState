# English-only intent recognition

Status: core implementation and evaluation completed in part; release gates remain open. Updated September 21, 2026. This is the next implementation sequence for [PLAN.md](../PLAN.md), superseding its earlier bilingual and manual-mode direction. Product decisions live in [PRODUCT.md](../PRODUCT.md).

## Outcome

During an explicitly activated voice session, say “Open Brave,” finish the utterance, and see Brave open without pressing Finish. Continue with “scroll down,” then dictate into a focused editor without changing modes. FlowState must distinguish literal dictation, commands, unsupported requests, and genuine ambiguity. English is the only supported interface, speech, and assistant-output language for this release.

This plan covers the full routing path: audio endpoint → intent → target/arguments → permission → execution → verification → visible result. Broader creative/email workflows remain in the main roadmap; a recognized intent does not make an unimplemented action available.

## Baseline before this implementation

- `SpeechSession.swift` has separate command/dictation modes and withholds most commands until a final transcript. Add utterance completion without ending an entire toggle/wake session.
- `FlowStateApp.swift` wires speech, HUD, explicit grants and execution. Preserve its generation-based cancellation and physical takeover handling.
- `convex/plans.ts` currently uses a hard-coded `0.55` confidence cutoff before a general planner. This is not an evaluated production policy.
- `convex/lib/typesafe.ts` has a reusable client, but `chooseCandidate` discards the probability distribution and permits missing confidence. Routing needs validated complete results.
- Native `NativePlan.swift` currently executes open-app, scroll and insert-text plans. The backend advertises more actions; intersect candidates with verified native/service capabilities instead of promising unsupported execution.
- Native settings have English/Traditional Chinese catalogs; speech, backend locale validators and the web companion also need migration. Removing a picker alone is insufficient.

## Architecture decisions

1. Start with Auto mode; keep optional Dictation only and Commands only overrides. Explicit “type …” preserves literal content. Explicit assistant address means a command request, not permission to execute it. Local Stop/Cancel and physical takeover bypass inference.
2. Detect utterance endpoints from local speech activity plus stable transcription. A 600–900 ms silence range is an experiment, not a release guarantee. Finalize one utterance, assign an ID, then continue listening only while the session remains active. Never execute a changing partial transcript.
3. Send Jev the completed utterance, minimal authorized text context, focus/editability, recent relevant interaction, explicit aliases, and bounded available candidates. Keep raw dictation separate from command normalization.
4. Jev selects intent (`dictation`, `action`, `clarify`, `unsupported`), an action and a target from supplied choices. Include unknown/none options. Questions evaluated together are independent; code enforces valid combinations rather than assuming one answer conditions another.
5. Resolve free-form arguments using deterministic parsing when reliable, otherwise the LLM; Jev cannot generate arbitrary email bodies, replacement sentences, paths or multi-step plans. Dictation insertion preserves exact recognized content unless cleanup was explicitly enabled.
6. All routes converge on one validated action contract, permission checks, target/focus freshness checks and serialized native executor. Confidence never grants access. No unrestricted shell or AppleScript generated by a model.
7. Reuse Convex authentication and server-side provider credentials. Firecrawl and AgentMail remain downstream capabilities for relevant workflows, not prerequisites for basic voice routing.

Fallback decision:

| Condition | Behavior |
|---|---|
| Evaluated intent/action/target gates pass; action supported and permitted | Execute and verify |
| Uncertain meaning, but text context can help | Bounded text-only LLM interpretation |
| Missing visual reference, such as “that button,” and observation/upload allowed | Capture relevant window; use vision-capable LLM |
| Conflicting intent, missing permission, protected field, unsupported action, or unresolved ambiguity | Explain or ask one short question; no action |
| Provider timeout/offline | Keep local Stop and validated explicit local commands available; no silent typing of unknown commands |

Low Jev confidence alone is not authority to capture or upload a screen. High confidence does not remove the need for vision when no target candidate exists. A screenshot cannot reveal an unstated user intention.

## 2. Measure Jev and select the fallback policy

Files: `scripts/evaluate-intent.ts`, `docs/testing/intent-evaluation.md`; add `convex/lib/intent_policy.ts` and `tests/backend/intent-policy.test.ts` after choosing an evidence-backed policy.

- [x] Run Jev on development data; refine atomic questions and candidates. Freeze prompts before calibration. Measure intent confusion, especially dictation→action, action/target accuracy, literal-text preservation, clarification rate, coverage and unsupported-action detection.
- [x] Record selected-option probability, top-two margin and TypeSafe confidence separately. Confidence is derived from the distribution, not a guarantee of real-world correctness or an independent probability of safe execution.
- [ ] Sweep thresholds on calibration data by action/risk and decision stage (intent, action, target). Select for unintended-action risk before optimizing coverage, latency or cost. Do not adopt a universal `0.8`/`0.9` by intuition.
- [ ] Compare Jev alone, the LLM baseline, Jev→text LLM, and Jev→vision LLM on relevant synthetic-screen cases. Include high-confidence Jev mistakes, not just cases selected for fallback. Measure whether extra context actually fixes mistakes.
- [x] Freeze the policy and evaluate once on untouched holdout. Report sample counts, error counts, confidence intervals and coverage-versus-risk; zero observed failures in a small set is not proof of safety. Expand evidence or keep a class in clarification mode if insufficient.
- [x] Validate fallback outputs against the same contract and permissions. Use explicit abstention for unresolved cases; do not trust an LLM's self-reported confidence as equivalent to calibrated Jev confidence. Bound escalation to one fallback attempt before clarification.
- [ ] Report p50/p95 model and end-to-end latency, fallback/screenshot rates and cost per 100 utterances using observed usage and current prices. Propose release targets from the report; automatic execution remains disabled for classes without enough evidence.

Verify: committed report records real results and selected thresholds with rationale. A separate regression suite includes every observed consequential failure. Changes after holdout require a new held-out evaluation.
