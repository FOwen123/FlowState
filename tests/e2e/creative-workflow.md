# Creative file workflow acceptance

Prerequisites: approved temporary folder with non-sensitive images, a chosen creative application and an authenticated test account. Paid generation, uploads, sharing and sending need exact destination/effect approval. Do not infer permission from a file-read grant.

1. Start from a clean task; select a file through the system picker or within an explicitly approved folder. Verify symlinks and changed files cannot escape or silently replace the approved selection.
2. Name the destination app and inspect the proposed attachment. Move/resize its window, change focus, or revoke the grant; verify stale actions do not upload.
3. Confirm the exact attachment/destination and dictate a creative request. Pause before any paid generation or external submission until separately authorized.
4. Wait without retaining desktop input ownership. Interact physically with another app; a result arriving must not steal focus or replay input.
5. Resume explicitly, observe current state and retrieve the result to the approved folder. Existing files must not be silently overwritten.
6. Prepare a sharing draft showing recipients and attachments. Confirm separately before sending. Undo must distinguish supported local changes from irreversible disclosure.
7. Interrupt at attachment, submission and retrieval boundaries; record failed/uncertain outcomes and verify there is no blind repeat.

Status: requires the owner's target app, sample folder and interactive native testing. A generic action registry or file picker alone does not pass this flow. Trip planning and return-request flows follow only after these reusable steps pass; purchases are excluded from routine tests.
